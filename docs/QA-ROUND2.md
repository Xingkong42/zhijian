## 6. 问题清单（真实可复现；按严重度）

### 6.1 🔴 F1（high）：磁贴双击头部**仍会最大化**，且最大化后的几何被写进 `tiles.json`（下次打开是全屏）

**现象（运行时实测）**：
1. 钉住一条笔记 → 磁贴窗口初始 `rect = 120,120 … 416,369`（296×249，正常小窗）；
2. **双击磁贴头部** → `IsZoomed(tile) = True`，窗口铺满屏幕；`tiles.json` 被改写成 **`{"x":-8,"y":-8,"width":1936,"height":1048}`**（-8/-8 是 Windows 最大化窗口的经典超屏矩形）；
3. 关闭后再钉同一条笔记 → 磁贴**以 1940×1057（全屏）尺寸打开**（`初始 rect L=0 T=23 size=1940x1057`）⇒ 被污染的几何会被"恢复位置"逻辑照搬。

**与声明的矛盾**【读码】：`src-tauri/capabilities/tiles.json:16` 明确写了 `core:window:deny-internal-toggle-maximize`（同文件 `:7` 的 `core:default` 会带入 `allow-internal-toggle-maximize`），capability 描述里也写明「用 deny-internal-toggle-maximize 显式否决（tauri 单测 denied_command_takes_precendence 证明 deny 优先于 allow）」。而 `pnpm check:tiles` 的静态断言「可达的最大化通路都被 deny 压住（通则，非写死 core:default）」**是通过的** ⇒ **静态自检绿、运行时被推翻**（正是 captain 本轮点名的「自检假绿 / 声明了但无效」类型）。

**最小复现**：`pnpm tauri:dev` → 选中一条笔记 → 点工具条「钉到桌面（磁贴）」（工具条右侧算起第 2 个图标）→ **双击磁贴顶部** → 窗口铺满 = 复现；查 `%APPDATA%\com.zhijian.app\tiles.json` 可见几何变成 `-8/-8/1936/1048`。

**影响**：① 明确设计要禁掉的行为仍然发生（用户双击磁贴头就会把便签铺满屏）；② 副作用是**持久化几何被污染** → 该笔记以后每次钉住都全屏打开。

**修法方向（我的推断，非实测）**：先确认该 deny 在本 Tauri 版本/该调用路径上是否真的被 ACL 咨询（`internal_toggle_maximize` 由注入脚本 `drag.js` 触发），必要时改为前端阻止双击或给磁贴窗口显式 `maximizable(false)`。**"deny 到底为什么没生效"需要在修复时用运行时验证闭环**，不能只看 capability 声明。

### 6.2 🟠 F2（medium）：「重建索引」/ 外部删除文件后，**侧栏计数徽标不刷新**

**现象**：外部删除 3 个 md → 打开设置 → 索引状态报「文件 7 · 笔记 10，文件数与索引笔记数不一致」→ 点「重建索引」→ 索引状态变为「文件 7 · **笔记 7**」，但**侧栏「全部笔记」仍显示 10**；此后切到「回收站」再回「全部笔记」，**列表自愈为 7 条**（表头 `全部笔记 · 7 条`），**侧栏徽标仍是 10**。

**最小复现**：造一条笔记 → 在文件管理器里删掉它的 `.md` → 设置 → 重建索引 → 观察设置面板显示 7、侧栏显示 10（且切换视图后仍不同步）。
